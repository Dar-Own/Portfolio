# Swap redemptions exhaust an outer-vault quota without consuming its liquidity

## Description

A permitted redeemer uses the inner-vault swap route when the outer vault lacks local output tokens. The outer quota is charged before route selection even though its own inventory is not spent. Repeating redemptions exhausts the shared quota; subsequently funded request settlement fails and victim requests stay pending.

The attacker needs redeemable tokens, permission/greenlist access, available swap/inner-vault liquidity and a finite outer quota. Unlimited quota is not affected. This is the internal tokensConfig allowance, not an ERC-20 spender allowance. Admin quota restoration provides recovery; no direct theft or greater-than-seven-day lock was established. Historical product balances and admin controls are not current-state claims.

#### Step 2 — Decrement every finite allowance

The helper subtracts the requested amount whenever the quota is finite, independent of the outer inventory delta.

Source: `contracts/abstract/Manageabl[project].sol:519-529`

```solidity
    function _requireAndUpdateAllowance(address token, uint256 amount)
        internal
    {
        uint256 prevAllowance = tokensConfig[token].allowance;
        if (prevAllowance == MAX_UINT) return;

        require(prevAllowance >= amount, "MV: exceed allowance");

        tokensConfig[token].allowance -= amount;
    }

```

## Proof of concept

The two-test Hardhat fixture deploys the vaults, assigns roles and greenlist access, mints synthetic attacker/victim tokens, and sets the shared internal quota to 90e18. Three ten-token swap redemptions pay 30 output units each without reducing outer-vault output inventory; quota falls 90→60→30→0. Once funded, three victim requests still fail bulk approval with MV: exceed allowance and retain pending status. The historical report records two passing tests. The observed failure is quota-driven availability loss; admin quota restoration remains possible.

**Proof limits:** Local vault and role fixtures; output liquidity and finite quota are prerequisites. No direct theft proved.
